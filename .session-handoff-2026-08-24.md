Seeding runs migrations first through the same `DatabaseLive` layer every capability uses; inserts are idempotent (`ON CONFLICT DO NOTHING`; existing auth.user by id or email skips the person) and require the `public.person_profiles` row before the better-auth user (FK on `auth.user.id = PersonId`). **Admin persona additionally needs** an `organization_global_administrator_grants` row (else org authority denies) and a `person_contact_profiles` row (else ROLE_ADMIN `/api/me` returns non-200).

## Operational gotchas learned

- `PUBLIC_APPLICATION_EFFECT_MODE` must be set to literal `'disabled'` to boot without effects config — `apps/backend/src/config.ts` rejects `undefined` ("must be disabled or http") rather than treating unset as disabled. Candidate ergonomic fix.
- better-auth's CSRF guard rejects requests without an `Origin` header. Browsers always send one; curl needs `-H 'Origin: http://127.0.0.1:5174'` or auth endpoints 403.
- Playwright project name is `chromium` (`--project=chromium`); `Desktop-Chrome` is a device descriptor, not a project name.
- Native dashboard specs are gated: `REAL_NATIVE_IDENTITY_E2E=1` must be exported or `auth.spec.ts` / `native-session-journey.spec.ts` skip themselves.
- Backend env contract now: `BACKEND_PG_URL` (shared by domain + auth schemas), `BETTER_AUTH_SECRET` (≥32 chars, hard-checked), `BETTER_AUTH_URL` (dashboard origin, default `http://127.0.0.1:5174`). `ADMISSION_AUTH_TOKENS` / `RECEIPT_AUTH_TOKENS` / `ORGANIZATION_AUTH_TOKENS` parse to empty maps when unset and are ignored by the person-keyed adapters — safe to omit entirely.

```markdown
## Summary

Replaces token-map authentication with a native identity authority built on
Better Auth. Sessions and credentials live in a dedicated `auth` schema of the
same PostgreSQL database; every actor resolves from the authenticated
PersonId, and authorization decisions flow through the Decision kernel.
Symfony's `api_login` surface is removed.

## User journey (reproduce)

1. Provision a disposable loopback PostgreSQL (rev 17), then seed an admin:
   `cd packages/database && IDENTITY_SEED_PERSONS='[...]' bun run identity:seed`
   (migrations 0015–0017 apply automatically; give the persona an
   `organization_global_administrator_grants` row and a `person_contact_profiles`
   row for ROLE_ADMIN `/api/me`).
2. Boot the backend (`BACKEND_PG_URL`, `BETTER_AUTH_SECRET` ≥32 chars,
   `BETTER_AUTH_URL=http://127.0.0.1:5174`,
   `PUBLIC_APPLICATION_EFFECT_MODE=disabled`) and the dashboard dev server.
3. Open `/login`, sign in with the seeded admin email/password.
4. Observe: redirect to `/dashboard`, `better-auth.session_token` cookie
   (HttpOnly, SameSite=Lax), admin profile rendered from `/api/me`.
5. Reload: session persists, dashboard renders again.
6. Click the user menu → "Logg ut": bounce back to `/login`, cookie removed.
7. Replay the captured cookie against the API: **401**.
```
