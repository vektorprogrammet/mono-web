# Getting started

This guide uses the v0.2 native API. It uses the local stack. Read [Run the local stack](/how-to/run-local-stack) before you start.

The generated [native API reference](/reference/native-api) owns the complete operation list, request schemas, response schemas, and status codes.

## 1. Read the health endpoint

```sh
curl -s http://localhost:8080/health
```

Expect a `200` response. The public OpenAPI document defines the response schema.

## 2. Sign in and save the session cookie

Set `DASHBOARD_ORIGIN` to the exact dashboard origin in the backend trusted-origin configuration. Better Auth owns this protocol route.

```sh
curl -s -c cookies.txt -X POST http://localhost:8080/api/auth/sign-in/email \
  -H "Origin: $DASHBOARD_ORIGIN" \
  -H "Content-Type: application/json" \
  -d '{"email":"you@example.org","password":"your-password"}'
```

The response sets the Better Auth session cookie. The local cookie name is `better-auth.session_token`. The secure cookie name is `__Secure-better-auth.session_token` outside explicit loopback development.

## 3. Read the current session

```sh
curl -s -b cookies.txt http://localhost:8080/api/session
```

A successful response contains session metadata. It does not contain a person identifier or credential. An absent, expired, or revoked session returns `401` with the generated Problem Details schema.

## 4. Read a public resource

```sh
curl -s http://localhost:8080/api/departments
```

This request does not need a session. Use the generated reference for the exact response schema.

## 5. Read a protected resource

```sh
curl -s -b cookies.txt http://localhost:8080/api/admission-periods
```

The operation can return `200` when the session has the required authority. It can return `401`, `403`, or a concealed `404` when the credential or authority is not valid.

## 6. Send a mutation

Every native `POST`, `PATCH`, and `DELETE` request needs one `Idempotency-Key` header. Generate a fresh cryptographically secure value for each command.

```sh
curl -s -b cookies.txt -X POST http://localhost:8080/api/content/articles \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: MDEyMzQ1Njc4OWFiY2RlZjAxMjM0NTY3ODlhYmNkZWY" \
  -d '{"title":"Hello native API","bodyHtml":"<p>First draft.</p>","departmentIds":["1"]}'
```

The request body does not contain `commandId`. A matching key and request replays the first response. A changed request returns an idempotency conflict.

An existing-resource mutation also needs its strong `If-Match` entity tag. Do not send `expectedRevision` in the request body.

## Error responses

Native errors use RFC 9457 Problem Details. The generated reference lists the exact error schema for each operation.

Common statuses include `400` for malformed HTTP input, `401` for an invalid credential, `403` for a denied authority decision, `404` for a missing or concealed resource, `409` for a conflict, `413` for a body that is too large, `422` for a schema failure, and `429` for rate limiting.

The v0.1 `{ "error": { "tag": "..." } }` envelope is historical. Do not use it for v0.2 requests.
