# Routes & API

The generated [native API reference](/reference/native-api) is the canonical reference for all public operations, schemas, and responses.

The v0.2 release projection contains 52 public external operations. One internal receipt-evidence operation stays outside the public OpenAPI document and public reference. The operation total does not claim native-to-legacy parity.

## Contract boundaries

`ExternalNativeApi` is the public native HTTP contract. `InternalNativeApi` is a separate internal contract. Better Auth `/api/auth/*` routes are credential-engine routes, not native operations.

The native contract groups operations by these resource areas:

- system sessions and health
- profile
- organization and directories
- admissions and applications
- recruitment
- receipts
- content and news

Open the generated reference to see the exact method, path, request, success, and Problem Details schemas for each operation. Do not copy that operation list into a handwritten page.

## Resource routes

Native collection resources use lower-kebab plural names. Action routes use the literal-colon form `/resource/{id}:action`. The v0.2 contract has no `/api/admin`, `/api/me`, slash-action, redirect, or compatibility route.

The internal receipt-evidence route uses a separate ingress. Path knowledge does not make that operation public.

`/api/open-admission-periods` is the anonymous admission-period projection. `/api/admission-periods` is the authenticated management representation. Credentials do not select between these representations.

## Authorization boundary

Each operation declares one `AccessSpec` beside its endpoint. The transport resolves the credential and principal, then the handler evaluates capability, scope, requirements, concealment, and decision time against current authority.

The operation name does not grant access. A failed authority requirement can return 403. Concealment can return 404. The generated reference lists the exact security requirement and error schema.

## HTTP boundary

Every external `POST`, `PATCH`, and `DELETE` requires one `Idempotency-Key` header. Existing-resource mutations use a validated strong `If-Match` entity tag. Public requests do not contain `commandId` or `expectedRevision`.

The server returns endpoint-specific RFC 9457 Problem Details for errors. A matching idempotent replay returns the first response. The generated reference lists each status and response schema.

## Legacy boundary

Version 0.1 is historical. Its callers and SDK used legacy route families, payload command identifiers, and an error-tag envelope. The v0.2 cutover removes those aliases and request assumptions.

Legacy API Platform resources remain under `apps/server/src/App`. The parity inventory compares legacy and native declarations. Similar path text does not prove behavioral parity.
