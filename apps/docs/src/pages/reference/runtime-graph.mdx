# Runtime and capability graph

The graph separates production authority from the synthetic preview. It also separates browser state from backend write authority.

```mermaid
flowchart TB
  User[Browser user]

  subgraph Production[Production authority at the inspected revision]
    Symfony[Symfony and API Platform]
    MySQL[(Legacy MySQL)]
    Symfony -->|reads and writes| MySQL
  end

  subgraph Preview[Development preview with synthetic data]
    Edge[Cloudflare apex edge Worker]
    Home[Homepage Worker]
    Dash[Dashboard Worker]
    Native[Native backend HTTP router]
    Edge --> Home
    Edge --> Dash
    Edge --> Native
  end

  subgraph Browser[Dashboard state]
    Route[React Router bridge]
    Foldkit[Foldkit Model, Message, update]
    Route -->|mounts| Foldkit
  end

  subgraph Backend[Native process]
    Http[Capability HTTP adapters]
    Runtime[One ManagedRuntime]
    Services[Effect Services]
    Layers[Live Layers]
    Postgres[(Native PostgreSQL)]
    Http -->|requires| Services
    Runtime -->|runs| Http
    Layers -->|provide| Services
    Layers -->|read and write| Postgres
  end

  User --> Symfony
  User --> Edge
  Dash --> Route
  Foldkit -->|commands through API boundary| Native
  Native --> Http
```
