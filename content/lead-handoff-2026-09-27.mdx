## Operator decisions taken today (2026-09-27)

1. **Migrations are frozen.** Nothing runs in production; every database is disposable; the legacy
   database is reached only through import commands. The 80 numbered migrations, the checksum
   registry, `just migration-hashes` and all upgrade proofs will be replaced by **one schema
   declaration** we edit directly. Design: `docs/specs/schema-declaration.md` on
   `refactor/schema-declaration-0927` (`bc2a82d0`) — **awaits approval of its mechanism and 11
   open questions.** No branch renumbers its migration. Branches fold their `0081`–`0084` DDL into
   per-context schema files and drop backfills.
2. **Interview correction window** (`A+B`, both interviewers): corrections are allowed from
   interview completion until the admission decision is recorded (no timer); after that the
   department board leader, or a current holder of the delegable staffing delegation, can reopen one
   window with a reason and an end instant **no later than the semester's end**; whoever reopens
   cannot correct under it. A post-decision correction never changes what the recorded decision
   acts on: a decision cites the recommendation it was based on.
3. **Admission standing** is one rule owned by Admissions: a pure `admissionReadiness(evidence)`
   plus one fenced SQL read. The readiness gate was **absent on `main`** (a "Nei" applicant could be
   issued onboarding); the two disagreeing SQL copies written during the review fixes are now one
   pure function (`fix/admissions-core-0926`).
4. **Architecture direction (FCIS + DDD)**: bounded contexts are a modelling and code-organisation
   boundary, not a runtime one; the core domain is a stateless library of pure algebraic APIs; the
   shell is one generic imperative runner; Layer requirements are declared as service interfaces
   and provided incrementally at composition roots; coalgebraic state only where state bound to
   operations is a real requirement. Draft spec: `docs/specs/architecture-consolidation.md` on
   `docs/architecture-consolidation-0927` (`cfc4782b`, status: draft).
5. **Concurrency** for the admission tool: EASY backfill, not strict FIFO. The machine's capacity
   numbers are derived at runtime, never copied into prose.
6. **Image and hosting are undecided.** No image has been built. `STATE.md` says DigitalOcean is
   the selected host but also that hosted Supabase runs PostgreSQL 17, and **Vercel appears in no
   record**. The only reachable record is `STATE.md:20` (Supabase, PostgreSQL 17) and `STATE.md:16`
   (DigitalOcean host, 2026-09-25). Alchemy has no Vercel, Supabase or DigitalOcean provider. The
   operator said "no alchemy, just podman" for the image, but Podman is not installed and rootless
   Podman needs a homelab change and a rebuild.
7. **Not a scheduling change**: the ADMISSION_FIXED_NOW deployment guard was not treated as part
   of the heavy-admission work.

## Known defects on `main` (not yet fixed)

- **Sign-in landing is blank under `/dashboard/`.** After the login redirect the router matches only
  `root` with no error; the body stays empty until a reload. `/dashboard/` is the **default mount**,
  so ordinary sign-ins are affected. [INFERENCE from React Router 8.3.0 source, not executed] the
  cause is lazy route discovery: no `routeDiscovery` option in `apps/dashboard/react-router.config.ts`
  and basename `/dashboard/`, so the login page ships only the root and login routes. Fix belongs in
  the router setup or a document redirect, preceded by a failing browser check. Recorded in
  `STATE.md` Known gaps. No journey covers it: every golden loads pages by URL.
- **The public rate limiter is one global in-memory bucket** keyed by the literal `'public'`
  (`apps/backend/src/http-api/public-rate-limit.ts:10`), 5 requests per 60 s per process. One
  anonymous caller can exhaust it for everyone; it resets on restart and doubles with two replicas.
  Better Auth's own limiter is in memory (`packages/database/src/auth-engine.ts`).
- **Pre-push "affected tests" select nothing when pushing `main`**: Turbo 2.8.13 compares against
  local `main`, which _is_ HEAD. 122 of 123 pre-push runs finished in about 1 s. Hosted CI has been
  the real gate. The fix is to set the base to the pushed ref (see
  `docs/specs/command-grammar.md`).
- **`just docs check` does not validate links inside an in-place document.** `content/(start)/state.mdx`
  is one line, `<include>../../STATE.md</include>`, so the links in `STATE.md` reach the site through the
  build. A dead link in `STATE.md` passed `just docs check` with 0 findings and failed the hosted
  `just docs build`. Only the build catches it, and the hosted Docs and Tests workflows both run it.
  Fix: make the check read in-place documents too, or have `just check` run the build.
- **FIXED on `main` (`afb11cf6`)**: `just land` could not merge a branch that changed
  `package.json` or `bun.lock`, because the pre-merge hook checked the merged tree against the main
  checkout's stale `node_modules` (Fumadocs died on `Cannot find package 'yaml'`). The hook now runs
  `bun install --frozen-lockfile` first, and Fumadocs landed through it. The rest of
  `docs/specs/land-installs-0927.md` (verifying in a temporary worktree so an aborted landing never
  moves main's `node_modules`) is still open.
- **`admission_period_outbox` is a dead outbox**: written, never read. The queue pilot's PersistedQueue
  store is the tenth delivery table.
- **Four of seventeen commands have no domain receipt** (admissions outcome, onboarding, placements,
  social events); social events also has no lock and no replay check.

## The architecture, as measured (`docs/architecture-consolidation.md`)

One Bun process, one PostgreSQL, one transaction per command. The domain is pure (0 mutable state,
23 genuine service interfaces, 0 pure functions wrapped as services). **But 14 of 17 commands decide
inline in database adapters**, and the persistence shell was copied per context: 9 outboxes and 7
worker fibers with 6 configuration families, 17 domain receipt tables in 4 incompatible shapes with
17 hand-written sequences, 21 audit + 5 history tables written from 25 files. Of 74 live SQL
functions, 50 are structural integrity that belongs in the database, **7 are business rules to move
to the pure core**, 16 are backstops (4 genuine, 12 existing only because fixtures, seeds and
importers write tables directly), 1 is dead. 82 cross-context table reads; the max foreign contexts
in one file is 5. 25 bounded contexts: co-change gives no merge signal (no pair above 0.11 Jaccard on
focused commits). 66 context-map relations: 21 translated, 31 raw table reads, 14 unbuilt.

**Rules not written although `docs/specs/repository-conventions.md` phase 3 requires them**: raw SQL
outside `packages/database` (5 backend files, 22 e2e files of which 10 are seeds, 39 files in
`tools/`), context boundary rules, `import/no-cycle`, outbox claim SQL, bare provider `fetch`,
`Date.now()` in domain and backend code. This is why agents keep writing ad-hoc SQL: nothing stops
them, and for many cross-context reads there is no owner query to call.

## Constraints a fresh lead must respect

- **Migrations are frozen.** No new numbered migrations. Fold existing `0081`–`0084` DDL into
  `packages/database/schema/` after the collapse lands. No renumbering, no upgrade proofs.
- **Writers work in their own worktree, never push; the lead lands with `just land` in the main
  checkout.** The pre-merge hook runs the full `just check` and `just test` on the merged tree and
  **has correctly aborted three landings today** (teardown test failure, stale construct page, the
  dependency install gap). It is the real gate; owner-run subsets are not enough.
- **A fresh worktree needs `devenv shell -- true` once** before commits, or the new hook refuses.
- **The heavy lock is one job at a time** until the admission tool exists; do not bypass it except
  with an explicit lead grant, and never set `VEKTORPROGRAMMET_HEAVY_LOCK` by hand.
- **Two DB copies of the decision-fence trigger** exist (Admissions `0084`, CorrectionWindow
  `0081`) by agreement in chat, not in a file. Whichever lands second drops its copy.
- Nothing may be pushed, deployed or provisioned without explicit operator authority.
