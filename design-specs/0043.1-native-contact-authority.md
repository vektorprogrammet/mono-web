# 0043.1 — Native public contact authority

Status: frozen after coordinating lead review, 2026-09-05.

Amends [0043](0043-public-contact-message-journey.md). The user authorized completing the native contact journey and local verification on 2026-09-05. This amendment replaces Symfony as the contact command authority and replaces the remote-only browser acceptance restriction with an isolated local real-IO journey. It does not authorize production deployment, external delivery, or close anti-abuse parity.

## Journey and ownership

A visitor opens `/kontakt` or an active department's contact route, sees that department's current public contact details, and submits name, email, subject and message. The native API resolves the recipient from the same authoritative organization data, validates and rate limits the command, and asks its configured delivery service to send one message. An empty HTTP 201 means the transport accepted the message; it does not establish inbox delivery.

Preserve the original Norwegian messages, route-derived department selection, draft retention on rejection, clear-on-success behavior, and pending-button behavior. Diagnose the observed page 503 separately; do not replace missing or invalid live data with synthetic fallback product content. Synthetic organization data is allowed only in isolated acceptance fixtures.

## Constraints

- One native typed HTTP operation and SDK operation replace the legacy fetch path. Regenerate derived HTTP artifacts and docs from their established sources.
- Reject malformed/oversize fields, malformed email and header-control characters; reject unknown or inactive departments and departments without a deliverable address. Browser input never chooses sender or recipient email.
- No contact-message row or retained message body. Rate-limit state may contain only bounded metadata needed to enforce the limit.
- Five attempts per one-hour fixed window per trustworthy visitor IP remains the API anti-abuse rule, sourced from `apps/server/config/packages/framework.yaml` (`contact_form`, `fixed_window`, limit 5, interval 1 hour), rather than the test/staging overrides. Normalize IPv4/IPv6 addresses to a canonical identity so alternate textual representations cannot split quota. Invalid schema requests need not consume a token, consistent with validation before the legacy processor. Count each validly decoded attempt before delivery; failure does not refund the token.
- Address identity must originate from the declared ingress/runtime boundary. Untrusted forwarded headers cannot alter it; SSR proxying must preserve distinct visitors. Unsupported or unconfigured trust topology fails closed. The implementation must document and test the supported topology before acceptance.
- Reuse existing delivery infrastructure where suitable; keep transport details outside domain meaning. The native command has one selected transport and never also dispatches to Symfony.
- Wait for transport acceptance before success. Rejection, timeout, absent configuration and unavailable transport produce failure. Do not automatically retry a potentially accepted send; a visitor-initiated retry is a new attempt and may duplicate mail after an ambiguous timeout. No exactly-once claim.
- Local verification uses an actual loopback HTTP delivery receiver and real PostgreSQL data, with no external provider requests, credentials or production data. Endpoint destination is explicit and local-run validation forbids non-loopback delivery.
- The reCAPTCHA-versus-rate-limit difference and original default-department/geolocation gap remain open.

## Acceptance and falsifiers

### Supported trust topology

The controlled ingress removes incoming contact-forwarding headers, derives and canonicalizes visitor IP from runtime socket/edge metadata, and supplies that address with a server-only ingress credential. The homepage Worker authenticates that hop and injects a typed React Router context value. Its server action forwards the canonical address with a separate backend credential to one explicit backend origin with redirects disabled. Backend contact command authentication metadata must describe this SSR credential requirement, even though the visitor journey requires no account. Wrong or missing credentials and wrong-hop credentials must cause rejection before quota mutation or delivery.

This costs a controlled ingress hop and two separately scoped server-only configuration values; missing configuration or unsupported topology fails closed. Tokens must never enter browser bundles, responses or logs. Local acceptance owns an actual loopback ingress deriving socket addresses and ephemeral credentials. Production ingress changes and secret provisioning remain outside this work.

### Gates

1. A committed clean revision passes affected backend, domain, HTTP/SDK and homepage checks; generated artifacts match their source. Report unavailable or unrelated failing checks explicitly.
2. A real browser opens the page through the actual built Cloudflare Worker homepage runtime backed by native HTTP and PostgreSQL, selects a live fixture department and submits. Observe one receiver acceptance with the selected department recipient, expected reply-to and message, plus browser success.
3. Observe rejected malformed input, inactive/unknown target, transport rejection and unavailable transport without browser success or unintended receiver acceptance.
4. Five decoded attempts from one trusted address are admitted; the sixth is rejected. A second trusted address has a separate allowance; forged forwarded headers do not rotate the first address's allowance. Concurrent attempts cannot exceed the allowance.
5. The browser draft remains after a rejected result; repeat click during pending sends one command. Run existing accessibility checks over changed states.
6. Evidence names exact revision, commands, observed endpoints, fixture ownership and cleanup. A skipped runner is unavailable evidence, never success.

The contract is false if recipient choice comes from submitted form fields, success precedes transport acknowledgement, invalid organization data becomes fabricated public contact data, proxy headers bypass the quota, two distinct trusted visitors share a proxy-wide quota, or local evidence is described as production readiness.
