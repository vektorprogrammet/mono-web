# Design spec 0066.1 - native domain schema boundary amendment

## Metadata

| Field | Value |
|---|---|
| Amends | Design spec 0066, `design-specs/0066-native-domain-schema-boundary.md` |
| Base | `aceb9abf9ca45842d7be1432680ce7b65bb08bb1` |
| Status | Amendment frozen; it supersedes the six-table limitation in 0066 |
| Operator boundary | Disposable PostgreSQL only. No production database, data import, deployment, credential change, provider, or external notification effect |

## Reason for amendment

Spec 0066 states that all native tables from migrations `0009` through `0021` MUST be in `public`, but its transfer steps enumerate only the six interview-conduct tables.

Migration `0015` creates schema `auth`. Therefore every native table created by migrations after `0015` can be created in `auth` when its SQL is unqualified. The correction must cover the complete post-identity inventory, not only Recruitment conduct.

This amendment changes the table inventory, transfer, qualification, and evidence requirements in 0066. All other 0066 requirements remain frozen, including Better Auth ownership of `auth`, preservation of spec 0054 identity, data and constraint preservation, migration safety, and the operator boundary.

## Complete post-0015 native table inventory

The implementation MUST use this checked inventory. The inventory is derived from the migration sources registered by `packages/database/src/migrations.ts`.

The complete post-0015 inventory contains seventeen tables. The inventory includes tables, not extensions, functions, triggers, rules, indexes, or migration bookkeeping tables. Those objects remain in scope through the qualification and preservation rules below.

The implementation MUST also derive and compare the checked inventory against the `CREATE TABLE` statements in these six migration sources. A missing, extra, or renamed table MUST fail the migration review. The implementation MUST not silently reduce the inventory to tables observed in one database.

## Amended frozen requirements

### 1. Full inventory transfer

Replace the six-table-only transfer requirement in 0066 with this rule:

> For every table in the seventeen-table inventory, the forward migration MUST perform schema-qualified catalog detection and collision-safe transfer from `auth` to `public`.

For each inventory table:

1. Detect `auth.<table>` and `public.<table>` using `pg_catalog` and explicit namespace predicates.
2. Do nothing when only `public.<table>` exists.
3. Transfer `auth.<table>` to `public` when only `auth.<table>` exists.
4. Fail before any transfer when both relations exist.
5. Preserve the table object and all rows during transfer.

The migration MUST process the complete inventory in one transaction, or in the strongest transaction boundary supported by the existing runner. A collision, missing dependency, permission error, or failed transfer MUST roll back every transfer in that run. It MUST not transfer the first six tables and then leave later tables in `auth`.

`ALTER TABLE auth.<table> SET SCHEMA public`, or an equivalent no-copy and no-rebuild operation, is required for each transfer. The migration MUST NOT use an unqualified relation name, `CREATE TABLE AS`, row copying, `DROP TABLE`, `TRUNCATE`, merge logic, or a compatibility table in `auth`.

### 2. Full inventory qualification

Every new or corrected SQL statement for any inventory table MUST qualify `public.<table>`. This includes table creation, indexes, foreign-key targets, rules, triggers, `ALTER`, DML, and verification queries.

The correction MUST explicitly qualify native functions and object targets created by migrations `0016` through `0021`. Existing immutable trigger and rule behavior MUST remain bound to the corresponding public domain object after transfer. Better Auth identifiers and tables MUST remain qualified in `auth` and untouched.

The migration and runtime MUST not depend on `search_path=auth,public` to locate any inventory table. A same-named object in `auth` MUST not change a qualified native read or write.

### 3. Full inventory collision policy

A collision exists when an inventory name has both `auth.<table>` and `public.<table>`. The migration MUST fail closed before changing any inventory table. It MUST identify every colliding name and MUST NOT merge, overwrite, drop, truncate, or select one row set.

A collision-free database with an absent `auth.<table>` and an existing `public.<table>` is already corrected for that table. Re-running the correction MUST leave that table unchanged.

### 4. Preservation scope

The preservation requirements in 0066 apply to every table in this amendment, not only conduct tables. The correction MUST preserve:

- row values and row counts;
- primary keys, unique keys, and exclusion constraints;
- foreign keys and delete behavior;
- check constraints, nullability, defaults, and identity ownership;
- indexes, rules, functions, triggers, and trigger bindings;
- organization, receipt, team-interest, schools, content, scheduling, and interview-conduct domain behavior.

The correction MUST not change authorization decisions, person-keyed identity, publication behavior, school directory behavior, team-interest submissions, receipt authority, scheduling, invitation responses, interview conduct, or audit and receipt semantics.

## Amended required evidence

All evidence remains on disposable PostgreSQL only.

### Inventory catalog evidence

After fresh replay and after upgrade correction, query `pg_catalog.pg_class` joined to `pg_catalog.pg_namespace` with explicit schema predicates. The evidence MUST list all seventeen inventory tables and their schema. It MUST show:

- every inventory table has `relnamespace = public`;
- no inventory table has `relnamespace = auth`;
- Better Auth tables remain in `auth`;
- existing scheduling tables remain in `public`;
- no inventory table has an unexpected duplicate in either schema.

The evidence output MUST name each table. A count of six conduct tables is not sufficient.

### Fresh replay

Run the complete migration runner from `0009` through the correction on an empty disposable database. Compare the catalog, columns, constraints, indexes, rules, functions, and trigger bindings for all seventeen tables with the checked inventory.

Run representative reads and writes for at least one table from each migration group `0016`, `0017`, `0018`, `0019`, `0020`, and `0021` through the normal pool. The operations MUST work without a manual `SET search_path` and MUST use the public relations.

### Upgrade correction

Run migrations through historical `0021` on a second disposable database while `search_path=auth,public`. Insert representative rows into every inventory table, including the identity-owned foreign-key paths and immutable content and conduct records. Record one row count and a stable row digest for every table.

Run only the forward correction. Repeat the catalog, row-count, row-digest, constraint, index, rule, function, and trigger evidence for all seventeen tables. The row counts and digests MUST remain equal. Run the correction again and show no further change.

### Search-path and collision evidence

Run qualified reads with `search_path=auth,public` and `search_path=public`. The results MUST be identical for every inventory table. In a disposable collision fixture, create one same-named `auth` relation and show that the correction fails before any inventory transfer or row change.

## Additional exact falsifiers

In addition to every falsifier in 0066, the amendment is false or incomplete if any one of these conditions occurs:

- Any table in the seventeen-table inventory is absent from the transfer logic or catalog evidence.
- `organization_global_administrator_grants`, either receipt-authority table, `organization_team_interest_registrations`, either schools table, or any content table remains in `auth` after replay or upgrade correction.
- The implementation reports only six conduct tables as the complete native-domain inventory.
- A table from migrations `0016` through `0020` is transferred by row copy, recreated, merged, or handled with an unqualified statement.
- The correction partially transfers the inventory before a later collision or failure, leaving mixed schemas in one database.
- A same-named `auth` relation changes a native read, write, verification result, or migration decision that uses the required qualified SQL.
- Any organization, receipt, team-interest, schools, content, scheduling, or conduct row, key, constraint, index, rule, function, trigger, or behavior changes during correction.
- Fresh replay and upgrade correction do not produce the same seventeen-table public inventory.

## Amended definition of done

1. The implementation records the seventeen-table inventory above and derives it from migrations `0016` through `0021` during review.
2. The forward migration transfers every inventory table from `auth` to `public` when required, with no copy, rebuild, merge, or data loss.
3. The transfer is transactionally collision-safe and idempotent for the complete inventory.
4. Every new or corrected migration, runtime, and verification statement uses explicit schema qualification for native domain relations.
5. Fresh replay and upgrade correction produce identical public placement for all seventeen inventory tables.
6. Catalog evidence names and verifies every inventory table, and separately verifies Better Auth ownership of `auth`.
7. All rows, keys, constraints, indexes, rules, functions, triggers, identity links, and existing behavior remain intact across the full inventory.
8. The exact falsifiers in 0066 and this amendment are exercised on disposable PostgreSQL databases, with no production effect.
