## Correct identity

This amendment replaces each docs deployment identity from the earlier specs.

| Field            | Correct value                              |
| ---------------- | ------------------------------------------ |
| Public URL       | `https://vector-docs.phibkro.org`          |
| Hostname         | `vector-docs.phibkro.org`                  |
| Stack            | `vektor-docs`                              |
| Stage            | `docs-dev-main`                            |
| Worker           | `vektor-migration-docs`                    |
| Logical resource | `MigrationDocs`                            |
| Local state      | `.alchemy/state/vektor-docs/docs-dev-main` |

The Vocs `baseUrl`, generated schema URLs, deployment guide, tests, and machine-readable state must use this identity.

## Wrong deployment correction

The docs-owned Worker was first deployed with the wrong custom domain `vektor-docs.phibkro.org`.

Use this order:

1. Plan the existing `vektor-docs` stack with both custom domains.
2. Confirm that the plan updates only `MigrationDocs` and does not delete a domain.
3. Deploy `vector-docs.phibkro.org` as the canonical domain while retaining the wrong domain as an alias.
4. Verify TLS, pages, assets, search, browser behavior, and machine-readable output on the correct hostname.
5. Plan the same Worker with only `vector-docs.phibkro.org`.
6. Confirm that the plan removes only the wrong docs custom domain.
7. Deploy the removal, then verify that the wrong hostname is no longer live.
8. Record both provider effects in sanitized evidence.

Do not remove the wrong domain before the correct hostname passes the live checks.

## Authority boundary

This correction can change only the existing docs-owned Worker and its two custom-domain bindings during the handover.

It must not change:

- `vektor.phibkro.org`
- `api.vektor.phibkro.org`
- `vektorprogrammet.no`
- an application Worker
- an existing preview resource
- production data
- a credential or profile record

The final state keeps the existing `vektor-migration-docs` Worker and local state. Only `vector-docs.phibkro.org` remains attached.

## Evidence

The evidence must record:

- the wrong hostname and existing Worker that were deployed
- the correct hostname that became live on the same Worker
- the plan and result for attaching the correct domain
- the plan and result for removing the wrong domain
- the fact that no second Worker or state namespace was created
- live checks for the correct site
- the final response from the wrong hostname
- source revision and artifact digests

Evidence must not contain credential values, profile labels, account IDs, cookies, or absolute operator paths.
