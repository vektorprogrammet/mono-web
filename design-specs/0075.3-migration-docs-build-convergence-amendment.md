# Design spec 0075.3 - migration docs build convergence amendment

## Metadata

| Field     | Value                                                                        |
| --------- | ---------------------------------------------------------------------------- |
| Stable ID | `0075.3`                                                                     |
| Status    | Frozen corrective amendment on 2026-08-31                                    |
| Amends    | `design-specs/0075-migration-docs.md`                                        |
| Reason    | Consecutive Vocs builds produce different output hashes for unchanged source |

## Problem

The deployment wrapper built the Vocs site before each Alchemy plan and deploy.

Vocs produces valid static output, but consecutive builds can use different chunk and module hashes. Alchemy then correctly reports a Worker asset update after deploy.

This behavior violates the required no-change convergence plan.

## Decision

Alchemy `Command.Build` owns the deploy build and its output hash.

Use one local build resource with this identity:

| Field             | Value                                                |
| ----------------- | ---------------------------------------------------- |
| Logical resource  | `DocsBuild`                                          |
| Command           | `bun run build`                                      |
| Working directory | `apps/docs`                                          |
| Output            | `apps/docs/dist/public`                              |
| Memoization       | Content hash of the docs source and nearest lockfile |

The `MigrationDocs` Worker consumes `DocsBuild.outdir` and `DocsBuild.hash.output`.

The deployment wrapper must not run another Vocs build before Alchemy. A separate build would change the output after the memoized hash became authoritative.

## State migration

The first plan after this amendment can report:

- create the local `DocsBuild` state record
- update the existing `MigrationDocs` Worker assets

The plan must not create another Cloudflare Worker, custom domain, DNS binding, or state namespace.

Deploy the bounded plan. Then run the same plan command again. It must report no changes.

## Authority boundary

`DocsBuild` is local deployment state in the existing `vektor-docs/docs-dev-main` namespace. It does not create a provider resource.

This amendment does not change the Worker name, public hostname, stage, custom domain, application resources, preview resources, data, or credentials.

## Evidence

The corrective evidence must record:

- the non-convergent plan observed before this amendment
- the bounded state migration plan
- the deployment result
- the final no-change plan
- the unchanged Worker and hostname identity

Evidence must not contain credential values, profile labels, account IDs, cookies, or absolute operator paths.
