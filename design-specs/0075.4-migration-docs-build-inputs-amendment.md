# Design spec 0075.4 - migration docs build input amendment

## Metadata

| Field     | Value                                                               |

| Stable ID | `0075.4`                                                            |
| Status    | Frozen corrective amendment on 2026-08-31                           |
| Amends    | `design-specs/0075.3-migration-docs-build-convergence-amendment.md` |
| Reason    | The docs generator reads repository files outside `apps/docs`       |

## Problem

The `DocsBuild` memo initially hashed only files under `apps/docs` and the nearest lockfile.

The reference generator also reads or checks these repository inputs:

- `design-specs/**/*.md`
- `evidence/**/*`
- `STATE.md`
- source references under `apps` and `packages`

A change outside `apps/docs` could therefore leave the memo unchanged. Alchemy could skip the generator and deploy stale reference pages.

## Decision

Keep `apps/docs` as the `Command.Build` working directory. Configure these memo inputs:

- `**/*`
- `../../design-specs/**/*.md`
- `../../evidence/**/*`
- `../../STATE.md`
- `../../apps/backend/src/**/*`
- `../../apps/dashboard/app/**/*`
- `../../packages/**/*`

Set `lockfile: true`. An explicit include list otherwise disables the default lockfile input.

The normal repository ignore rules continue to exclude generated output and dependencies.

## State update

The first plan after this amendment can update `DocsBuild` because its memo properties changed. It can update `MigrationDocs` only if the new build output hash changed.

The plan must not create or delete a Cloudflare resource, custom domain, DNS binding, or state namespace.

Deploy the bounded plan. Then run the same plan command again. Both `DocsBuild` and `MigrationDocs` must report no change.

## Evidence

Append the memo-property plan, deploy result, and final no-change plan to the hostname-correction evidence.

Evidence must not contain credential values, profile labels, account IDs, cookies, or absolute operator paths.
