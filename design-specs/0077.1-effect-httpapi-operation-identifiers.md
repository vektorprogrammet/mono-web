# Design spec 0077.1 - Effect HttpApi operation identifier amendment

## Metadata

| Field | Value |
|---|---|
| Amends | Design spec 0077, `design-specs/0077-effect-httpapi-contract.md` |
| Base | `4f6c86ac55d54267695dc01e8598077ee927d4d7` |
| Status | Frozen before implementation |
| Effect source | Official and installed `effect@4.0.0-rc.109` |
| Operator boundary | Repository-local contract and generated artifact only; no deploy, push, shared database, provider, credential, or external effect |

## Reason for amendment

Design spec 0077 says that public OpenAPI operation IDs are the bare endpoint identifiers in its route table. Effect RC109 derives a non-top-level group operation ID as `<group identifier>.<endpoint identifier>`. The implemented groups are intentionally not top-level, so `OpenApi.fromApi(NativeApi)` produces fully qualified IDs such as `organization.createDepartment`.

This amendment replaces only the operation-ID rule in spec 0077. All route, method, path, schema, status, authority, handler, runtime, OpenAPI exclusion, and Better Auth requirements remain frozen. The truthful native inventory is 47 public operations plus one internal operation. Equality between the legacy Symfony route count and native route count is not a parity metric or falsifier; successor spec 0078 compares composed user-intent capability instead.

## Amended frozen operation-ID contract

Every native operation has one stable fully qualified identifier:

```text
<HttpApiGroup.identifier>.<HttpApiEndpoint.identifier>
```

The group identifiers are `system`, `directory`, `profile`, `organization`, `admissions`, `recruitment`, `receipts`, `content`, and `internal`. The endpoint identifiers remain the identifiers in the spec 0077 route table. Thus the table's `createDepartment` endpoint has operation ID `organization.createDepartment`, and the internal `readReceiptEvidence` endpoint has operation ID `internal.readReceiptEvidence`.

Groups MUST remain non-top-level unless a later frozen amendment migrates every operation identifier and every consumer atomically. Handwritten OpenAPI overrides MUST NOT strip the group prefix. The generated identifiers are collision-resistant capability atoms for future composed contracts and authorization projections; consumers MUST use the complete qualified value rather than infer an endpoint from the suffix.

## Required evidence

The implementation and drift gate MUST derive operation IDs from `OpenApi.fromApi(NativeApi)` and MUST prove:

1. the public projection contains exactly 47 operations and 47 unique fully qualified IDs;
2. every public ID has exactly one known group prefix and a non-empty endpoint suffix;
3. representative IDs are exact: `system.health`, `organization.listDepartments`, `profile.readOwnProfile`, `organization.createDepartment`, `admissions.createAdmissionPeriod`, `recruitment.readSchedulingBoard`, `receipts.submitReceipt`, and `content.listNews`;
4. the executable excluded endpoint retains the internal capability atom `internal.readReceiptEvidence` while remaining absent from public OpenAPI;
5. Better Auth `/api/auth/*` remains absent from the native contract and generated OpenAPI;
6. deterministic generation and `--check` continue to compare exact repository-owned bytes.

## Falsifiers

The amendment fails if:

- an operation ID is bare, rewritten by a manual OpenAPI override, duplicated, or changes because of serialization order;
- an operation ID lacks its actual RC109 group identifier;
- the internal capability appears in public OpenAPI;
- the legacy Symfony operation count is used to add or delete native routes;
- generated OpenAPI drift is accepted; or
- any route, behavior, authority, runtime ownership, Better Auth boundary, or exclusion from spec 0077 changes as part of this amendment.
