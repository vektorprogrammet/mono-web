## 1. Scope and authority

This amendment freezes the final v0.2 native resource routes and their access assignments. It replaces the route table in specification 0077.

Specification 0077.1 still owns the operation-ID form:

```text
<HttpApiGroup.identifier>.<HttpApiEndpoint.identifier>
```

The matrix contains 53 rows. It has 52 external operations and one internal operation. The counts come from the rows, not from a separate route constant.

The external matrix contains no `/admin`, `/me`, slash action, alias, redirect, or compatibility route.

Collection resource names use lower-kebab plural nouns, except for one handoff-specific route. The capability-selected `/api/recruitment/invitation-response` singleton is an explicit amendment exception.

The other known singleton resource exceptions remain `/health`, `/api/profile`, and `/api/session`. The fixed `/api/receipt-approval-queue` path is a queue projection, not a collection resource.

`/api/open-admission-periods` is the anonymous admission-period projection. `/api/admission-periods` is the authenticated management representation. The two routes never select a representation from ambient credentials.

Better Auth and OAuth protocol routes are not native operations. Section 8 freezes their boundary.

## 2. Matrix notation and schema dependencies

Each `AccessSpec` cell has this exact field order:

```text
exposure;
accepted credential mechanisms;
principal kinds;
capability expression;
canonical scope resolver;
requirements;
concealment;
decision time
```

`[]` means that the endpoint adds no requirement. Grant and rule requirements still apply. `Reveal` and `NotFound(...)` are the 0055.1 concealment variants.

`None` in a request column means no body, path parameter, or query schema. A named query or path schema remains part of the request contract.

All external `POST`, `PATCH`, and `DELETE` rows require `Idempotency-Key`. The matrix shows this requirement as `Idempotency-Key + ...`. Public bodies and responses contain no `commandId`.

An existing-resource mutation also shows `If-Match` where the handoff already requires an ETag. Specification 0080.1 owns the ETag source and detailed precondition behavior.

The following values are explicit implementation dependencies. They are not placeholder schemas:

| Dependency | Required owner and result |
| --- | --- |
| `DEP-PROBLEM::<operationId>` | Specification 0080.1 must freeze one endpoint-specific RFC 9457 error-union schema identifier and exact statuses. |
| `DEP-MUTATION-REQUEST::<operationId>` | The implementation owner must derive the public request from the cited current schema. It must remove `commandId`, path duplicates, and revision fields moved to HTTP headers. |
| `DEP-MUTATION-SUCCESS::<operationId>` | Specification 0080.1 must freeze the first-result and replay representation. The schema must expose no `commandId`. |
| `DEP-PATCH::<operationId>` | Specification 0080.1 must freeze PATCH null/delete semantics, the strong-ETag source, and the final payload identifier. |
| `DEP-OPEN-ADMISSION-PERIODS` | Admissions must add a cache-safe anonymous projection schema. It must not reuse `AdmissionPeriodListResponse`. |
| `DEP-ADMISSION-PERIOD-MANAGEMENT` | Admissions and 0080.1 must remove `lastCommandId` from the current management projection and freeze the final schema identifier. |
| `DEP-PEOPLE-DIRECTORY` | Profile and Organization must freeze the final people projection identifier. It replaces the `AdminUserDirectory*` public names. |
| `DEP-RECEIPT-APPROVAL-QUEUE` | Economy must add the distinct approval-work projection required by the handoff. It must not reuse `ReceiptListResponse`. |

An implementation cannot replace a dependency with a guessed schema, `unknown`, an untyped object, or the v0.1 error envelope.

Row 33 intentionally has no `If-Match`. It creates a new interview child resource and does not update the application row.

The current transaction reads the application as a canonical parent, rejects an existing interview with `RecruitmentApplicationAlreadyAssigned`, then inserts the interview, question snapshots, receipt, and audit. `RecruitmentAssignmentCandidateSchema` exposes no application revision that can produce a strong ETag.

The transaction and unique assignment constraint order concurrent creates. `Idempotency-Key` controls replay, and an existing assignment remains a 409 conflict.

If a later implementation updates the application row, 0080.1 must first add an item representation and strong ETag source. That change must also add `If-Match` to row 33.
