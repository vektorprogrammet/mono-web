## 1. Purpose

Design spec 0077.2 freezes 52 external operations and one internal operation.
That matrix omits five reads that current first-party routes still call.

This amendment adds those five reads to `ExternalNativeApi`.
The final count is 57 external operations and one internal operation.

This amendment does not add mutations.
It does not add compatibility routes or SDK forwarding methods.
It does not change the internal native operation.

## 3. Contract authority

`ExternalNativeApi` remains the only external native route root.
The five rows in this amendment extend section 3 of design spec 0077.2.

Each endpoint carries one colocated `AccessSpec`.
The runtime decision and generated `x-vektor-access` use that same value.

The backing provider supplies evidence for fields and eligibility.
It is not a second route authority after the cutover.

The implementation must port each provider query to a native query boundary.
It must not proxy a native request to Symfony.

Unknown properties fail decoding.
All arrays preserve the backing query order.

`Int` means a safe integer.
`Rfc3339Instant` uses the existing native time schema.

## 6. Registry changes and access dependencies

The dashboard row reuses three closed entries:

- capability `profile.read-self`
- scope resolver `profile.current-person`
- requirement `profile.owner`

The implementation adds these capability IDs to `CAPABILITY_TYPE_IDS`:

- `admissions.read-statistics`
- `scheduling.read-assistants`
- `scheduling.read-substitutes`

Each new capability has `ruleTarget: false` and `objectCapability: false`.
The implementation does not add these IDs to the persisted rule-target schema.

The implementation adds these scope resolver IDs to `SCOPE_RESOLVER_IDS`:

- `content.public-sponsors`
- `admissions.statistics`
- `scheduling.assistants`
- `scheduling.substitutes`

This amendment adds no domain ID, resource kind, or requirement ID.
The current registries are at `packages/domain/src/authz/access.ts:33-61,98-133,150-167,178-215`.

### 6.1 Public sponsor scope

`content.public-sponsors` returns one global `content` context.
It produces no candidate grant because the capability expression is `None`.

### 6.2 Protected scope selection

The protected resolvers use the current Organization authority.
They do not trust a department, semester, role, or grant from the request.

Each resolver selects the actor department and the current semester.
Each resolver fails closed if the actor department is absent or ambiguous.
Each resolver returns one `admissions` context for the selected department.

The `scheduling` operation group does not create a domain authority.
Admissions owns the application and admission-period data for both scheduling lists.

### 6.3 Exact eligibility ceiling

The current Organization projection remains the role authority.
`mapOrganizationAuthorityToProfileRole` derives the role from active state.

The statistics and substitute reads do not accept a role below `ROLE_TEAM_MEMBER`.
The assistant read does not accept a role below `ROLE_TEAM_LEADER`.

The native eligibility ceiling is:

| Operation | Accepted derived roles |
| --- | --- |
| `admissions.readAdmissionStatistics` | `ROLE_TEAM_MEMBER`, `ROLE_TEAM_LEADER`, `ROLE_ADMIN` |
| `scheduling.listAssistants` | `ROLE_TEAM_LEADER`, `ROLE_ADMIN` |
| `scheduling.listSubstitutes` | `ROLE_TEAM_MEMBER`, `ROLE_TEAM_LEADER`, `ROLE_ADMIN` |

The legacy statistics and substitute resources require `ROLE_TEAM_MEMBER`.
The legacy assistant resource requires `ROLE_TEAM_LEADER`.

The current access registry has no grant source for these new capabilities.
Therefore, the access owner must resolve `DEP-GRANT` before endpoint implementation.

`DEP-GRANT` must name the existing authority facts that produce each candidate grant.
It must prove equivalence to the eligibility ceiling in this section.
It must not infer authority from a request value or a UI role string.
It must not add a persisted rule or widen eligibility.

## 8. Caller disposition

Design spec 0077.2 section 7.3 changes as follows.

| Removed SDK call | Required generated call | Required caller change |
| --- | --- | --- |
| `client.me.dashboard()` | `client.dashboard.readSummary()` | Use `DashboardSummary`. Remove unsupported count-field decoding. |
| `client.public.sponsors()` | `client.content.listSponsors()` | Use `logoImagePath` and `size`. Do not synthesize `logoUrl`. |
| `client.admin.admissionStats()` | `client.admissions.readAdmissionStatistics()` | Render only the eight provider-backed fields. |
| `client.admin.scheduling.assistants()` | `client.scheduling.listAssistants()` | Consume the returned array. Do not read `.items`. |
| `client.admin.scheduling.substitutes()` | `client.scheduling.listSubstitutes()` | Consume the returned array. Do not read `.items`. |

The `client.me`, `client.public`, and `client.admin` namespaces still leave the SDK.
Their deletion occurs only after each mapped caller uses a generated operation.

`recruitment.readSchedulingBoard` does not replace either scheduling list.
It remains the interview scheduling-board operation from design spec 0077.2 row 32.

`recruitment.readAssignmentBoard` does not replace either scheduling list.
It remains the application assignment-board operation from row 31.

### 8.1 Fixture boundary

Explicit fixture mode can use fixture data.
Real mode and native mode must not use fixture data after a read failure.

A failed real read produces the route's explicit unavailable or error state.
A failed real read must not produce plausible business values.

The statistics route must remove its current real-mode mock fallback.
The other four routes must not add such a fallback during migration.

## 9. Password recovery boundary

Password recovery stays outside both native API roots.
It does not receive an operation ID or an `AccessSpec` in this amendment.

A separate amendment owns the Better Auth recovery routes and callback.
This amendment does not change or delete a password-recovery handler.

## 11. Mechanism boundary

This amendment freezes observable reads and access decisions.
It does not freeze internal SQL, repository names, or service composition.

The implementation must satisfy all section 7 dependencies before handler work.
The native query services then reproduce the provider selection and projection.

The implementation keeps one route authority.
It keeps one access value per endpoint.
It keeps one generated SDK projection.

No response uses a legacy Hydra or `Page` envelope.
No caller converts a generated result into a legacy response envelope.

## 12. Falsifiers

The implementation is false if one condition occurs:

1. Reflection reports a count other than 57 external and one internal.
2. One operation has a different method, path, or operation ID.
3. A success response has a field that its backing provider does not warrant.
4. A response keeps an unsupported old SDK field as an alias.
5. A scheduling list uses a recruitment board as its data source.
6. A protected resolver trusts a request-supplied authority value.
7. A protected operation accepts a role outside its section 6.3 ceiling.
8. An eligible role loses the bounded read for its canonical department.
9. A read uses `Transaction` or causes a write effect.
10. A native handler proxies the legacy Symfony route.
11. Real mode returns fixture or mock business data after a failure.
12. A generated artifact reports 52 external operations.
13. First-party runtime code keeps one of the five removed SDK calls.
14. A caller reads `.items` from either generated scheduling array.
15. Password recovery appears in either native API root.
16. A section 7 dependency remains unresolved when its endpoint lands.
17. A generator or runtime uses a second route or access registry.
