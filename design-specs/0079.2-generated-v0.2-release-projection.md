## Amendment authority

This amendment replaces the 47-operation scope in design spec 0079 with 52 public external operations.
It keeps one internal operation outside the public OpenAPI document and public documentation.
It replaces the v0.1 SDK selection with the generated v0.2 SDK contract in this amendment.

Design spec 0079.1 applies without changes.
All other compatible requirements in design spec 0079 remain active.
If a requirement conflicts with this amendment, this amendment has authority.

## Goal

Generate one deterministic local projection of the v0.2 `NativeApi` contract.
The projection supplies OpenAPI, SDK, server, documentation, and release metadata artifacts.
Each artifact identifies its canonical source and release version.
No generated artifact becomes a second contract source.

## Canonical contract root

`NativeApi` is the sole route and operation root for this release projection.
The repository represents this contract with `ExternalNativeApi` and `InternalNativeApi`.
`ExternalNativeApi` contains the 52 public external operations.
`InternalNativeApi` contains the one separately mounted internal operation.

Generators reflect these roots directly.
They do not read a copied route table, SDK method list, or documentation inventory.

The public OpenAPI, generated SDK, and public API documentation use only `ExternalNativeApi`.
Server metadata reflects both roots and records each operation's visibility.
The release manifest records the artifact paths, counts, digests, version, and source provenance.

## Observable release contract

### Public OpenAPI

`packages/http-api/openapi.json` is an OpenAPI 3.1 document.
Its `info.version` is `0.2.0`.
It contains exactly 52 operations with unique operation identifiers.

The document excludes all Better Auth `/api/auth/*` routes.
It also excludes the internal receipt evidence operation.
Every documented operation comes from `ExternalNativeApi` reflection.

### Generated SDK

`@vektorprogrammet/sdk` has version `0.2.0`.
Its Effect client comes from `HttpApiClient.make(ExternalNativeApi)` or an equivalent public Effect API.
The generated method inputs preserve the reflected parameter, query, payload, and header schema types.

The Promise surface is a mechanical adapter over the Effect client.
It does not own routes, request schemas, response schemas, or error mappings.
The package exposes the generated operation inventory as `./operations`.

The v0.2 package removes all v0.1 method aliases and domain aliases.
It also removes SDK-local route, schema, transport, and response-decoder projections.
No compatibility shim restores a removed v0.1 symbol or object shape.

### First-party caller cutover

The same clean cutover migrates every tracked first-party `NativeApi` caller.
This scope includes dashboard runtime code, Foldkit commands, first-party tests, fixtures, and documentation examples.

Each caller uses generated v0.2 group names, operation names, request types, and result types.
Each caller uses the v0.2 method and route from `ExternalNativeApi`.
Consumers use the v0.2 result shape without a legacy envelope adapter.

Native callers do not use `/api/admin` or `/api/me`.
An action route uses the literal-colon form `/resource/{id}:action`.
It does not use the old slash-action form `/resource/{id}/action`.

A mutation sends its idempotency value in `Idempotency-Key`.
It does not send `commandId` in the payload.
An existing-resource mutation sends its revision condition in `If-Match`.
It does not send `expectedRevision` in the payload.

A genuinely legacy-Symfony-only journey remains explicitly marked as legacy.
Such a journey targets the legacy Symfony base, not the `NativeApi` base.
It does not import or imitate the generated v0.2 SDK.

### Server metadata

The generated server metadata has release version `0.2.0`.
It contains 52 operations marked `external` and one operation marked `internal`.
The metadata contains 53 unique operation identifiers in total.

The internal operation stays on its separate ingress.
Its presence in server metadata does not make it a public operation.

### Documentation projection

Vocs mounts `packages/http-api/openapi.json` at `/reference/native-api`.
The generated landing page states that the public API contains 52 operations.
The page states that one internal operation is not in the public reference.

The API pages get methods, paths, schemas, and operation text from the OpenAPI document.
No Markdown file owns a duplicate route list.
The human `Routes & API` page remains the route-family overview.

The code reference continues to use source comments as specified by design spec 0079.
The toolchain and TypeScript compiler alias come from design spec 0079.1.
Generated code pages do not restore removed v0.1 SDK symbols.

### Release manifest and provenance

`packages/http-api/release-manifest.json` is the machine-readable release record.
It records release version `0.2.0` and the 52 external plus one internal counts.
It records these generated artifacts:

- `packages/http-api/openapi.json`
- `packages/sdk/native-api-operations.json`
- `apps/backend/src/generated/native-api-metadata.json`

The manifest records one SHA-256 digest for the exact bytes of each artifact.
It records the canonical contract, generator path, Effect version, and governing design specifications.
It contains no timestamp, host path, process identifier, or other variable input.

The API documentation reads release facts from the OpenAPI document or release manifest.
It does not copy the release count, version, or artifact digests into a second data source.

## Mechanism boundary

The generator can use Effect reflection, stable JSON encoding, and SHA-256 hashing.
It can use a small adapter to expose Effect-generated methods through Promises.
It can use a small adapter for Vocs-compatible `@effect/docgen` Markdown.

These adapters can change representation only.
They must not add operations, rename methods, weaken types, or invent API prose.
They must not create a second route registry or response engine.

Source TypeScript owns the HTTP contract and source comments.
Generated JSON owns no editable policy.
Generated Markdown owns no editable prose.
The manifest owns release evidence, not authorization or routing behavior.

## Deterministic generation and checks

One release generator writes OpenAPI, the SDK operation inventory, server metadata, and the release manifest.
The docs generator consumes those checked artifacts and the selected source comments.

Generation sorts object keys and operation identifiers before it writes JSON.
Each generated text file ends with one newline.
The manifest hashes the final bytes of each listed artifact.

Check mode generates candidates without changing tracked files.
It compares exact bytes and rejects each missing, changed, or extra owned artifact.
Two consecutive generation runs must produce identical bytes.

The OpenAPI check asserts all of these facts:

1. The document uses OpenAPI 3.1.
2. The document has version `0.2.0`.
3. The document contains exactly 52 public external operations.
4. Every public operation identifier is unique.
5. No Better Auth route is present.
6. No internal operation is present.

The server metadata check asserts 52 external operations and one internal operation.
The manifest check recalculates every recorded SHA-256 digest.
The SDK type check compares reflected mutation header types with their canonical schema types.
A focused request check observes `Idempotency-Key` and `If-Match` on a generated mutation.

A deterministic scan examines all tracked first-party caller sources.
It rejects removed SDK symbols, `/api/admin`, `/api/me`, old slash-action routes, and obsolete mutation payload fields.
The scan limits payload-field checks to native HTTP caller and fixture boundaries.

An explicit allowlist identifies each genuinely legacy-Symfony-only journey.
Each allowlist entry records its source path, legacy base, and reason.
The scan rejects an unmarked legacy exception or a legacy entry that targets `NativeApi`.

Focused caller checks cover dashboard runtime code, Foldkit commands, first-party native tests, fixtures, and documentation examples.
These checks use the reflected v0.2 request and result types.

The browser acceptance journey uses the actual dashboard and backend surfaces.
It signs in, opens `/dashboard/profile`, and observes `GET /api/profile`.
It submits a profile change through `PATCH /api/profile` and observes the updated v0.2 profile result.
The mutation request contains `Idempotency-Key` and `If-Match`.
The journey's network log contains no removed NativeApi route.

## Non-goals

This amendment makes no native-to-legacy capability parity claim.
It adds no parity comparator or placeholder parity page.
It does not publish a package or documentation site.
It does not deploy an application or change a provider resource.
It adds no caller compatibility shim for a removed SDK surface.

## Falsifiers

The implementation fails this amendment if any statement is true:

- The public OpenAPI document contains other than 52 operations.
- The internal operation appears in public OpenAPI or public API documentation.
- A Better Auth `/api/auth/*` route appears in public OpenAPI.
- OpenAPI, SDK operations, or server metadata comes from a copied route table.
- The SDK defines handwritten operation parameter aliases or response mappings.
- The SDK exports a removed v0.1 method alias or compatibility object shape.
- The Promise client owns behavior that is not present in the Effect client.
- Server metadata omits the internal operation or marks it as external.
- Any generated release artifact has a version other than `0.2.0`.
- The manifest count differs from 52 external plus one internal operation.
- A recorded digest differs from the exact bytes of its artifact.
- Generation output changes between two runs with unchanged source.
- Check mode accepts a missing, changed, or extra owned artifact.
- Generated Markdown becomes an editable source of API or code prose.
- A public page states or implies native-to-legacy capability parity.
- The implementation publishes, deploys, or changes a remote resource.
- A tracked first-party `NativeApi` caller uses a removed v0.1 SDK symbol or object shape.
- A tracked first-party `NativeApi` caller targets `/api/admin` or `/api/me`.
- A tracked first-party `NativeApi` caller uses a slash-action route.
- A native mutation sends `commandId` or `expectedRevision` in its payload.
- A caller converts a v0.2 result into a legacy response envelope.
- A legacy-Symfony-only journey targets the `NativeApi` base or lacks an explicit legacy marker.
- A removed-symbol scan skips a tracked first-party caller scope.
- A scan allowlist entry lacks a source path, legacy base, or reason.
- A focused caller check still uses a v0.1 operation name, route, request, or result.
- The actual browser journey does not complete the v0.2 profile read and update flow.
