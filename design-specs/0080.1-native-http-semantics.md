# Design spec 0080.1 — native HTTP semantics amendment

## Metadata

| Field               | Value                                                                                                      |

| Status              | Frozen before implementation                                                                               |
| Amends              | 0077, 0077.1, 0077.2, and 0080                                                                             |

## 1. Scope and precedence

This amendment freezes the v0.2 HTTP behavior of every operation in 0077.2. It does not add, remove, rename, or redirect a route.

The method, path, operation ID, effect, and `AccessSpec` in 0077.2 remain unchanged. This amendment resolves every `DEP-*` value in that matrix.

The following precedence applies:

1. Specifications 0054.1, 0055.1, 0056.2, and 0082 own identity, access, and OAuth behavior.
2. Specification 0077.2 owns the route and access matrix.
3. This amendment owns native HTTP request, response, replay, precondition, cache, CORS, and Problem Details behavior.
4. Existing v0.1 transport behavior does not override this amendment.

Current CORS behavior, generated OpenAPI, and legacy routes can differ from this frozen contract. Each difference is an implementation gap, not accepted compatibility.

Better Auth and OAuth protocol routes are not native operations. Their protocol-specific errors remain outside this Problem Details contract.

## 3. Idempotency

### 3.1 Header contract

Every external `POST`, `PATCH`, and `DELETE` operation requires one `Idempotency-Key` header. Multiple header fields or a comma-joined value fail with 400.

The decoded key has this grammar:

```abnf
idempotency-key = 22*128(base64url-char)
base64url-char = ALPHA / DIGIT / "-" / "_"
```

The value is case-sensitive. Padding, whitespace, quotes, periods, slashes, and non-ASCII bytes are invalid.

A client must generate the key from at least 128 bits of cryptographically secure random input. The server enforces syntax and length, but it cannot prove entropy.

This valid deterministic example is 43 characters:

```text
MDEyMzQ1Njc4OWFiY2RlZjAxMjM0NTY3ODlhYmNkZWY
```

The maximum decoded header length is 128 ASCII characters.

### 3.2 Identity tuple and internal command ID

The idempotency identity is this exact tuple:

```text
(
  credentialSubject,
  qualifiedOperationId,
  normalizedTarget,
  idempotencyKey
)
```

`credentialSubject` is one of these values:

- `Person:<PersonId>` for a cookie or delegated OAuth token;
- `Service:<ServicePrincipalId>` for a service token;
- `Capability:<CapabilityId>` for an object capability;
- `Anonymous` for an anonymous command.

The tuple never contains raw cookie, bearer, capability, client secret, or session bytes. `CapabilityId` is the domain-owned stable capability identity after credential resolution.

`qualifiedOperationId` is the exact operation ID from 0077.2. `normalizedTarget` is the route template with each decoded path identity encoded as one RFC 3986 path segment.

A collection create uses the collection route as its target. Query and body values belong to the request digest, not the target.

The adapter maps the tuple to the domain command ID:

```text
httpv2_<base64url-no-pad(SHA-256(JCS(identity-tuple)))>
```

The stored and public response never exposes this command ID.

### 3.3 Canonical semantic request and digest

The adapter decodes the request against its endpoint schema before it calculates the digest. It rejects duplicate JSON member names before schema decoding.

The canonical semantic value is:

```json
{
  "body": {},
  "ifMatch": null,
  "ifNoneMatch": null,
  "query": {}
}
```

The adapter parses conditional headers before it constructs this value. A malformed conditional header fails before digest calculation.

For a mutation, `ifMatch` is the one validated strong opaque tag in canonical quoted wire form. It has no surrounding optional whitespace.

For example, the semantic value stores `"\"vkr2.AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\""`. Header folding or optional whitespace cannot change this string.

`ifNoneMatch` is one of these exact values:

- `null` when the header is absent;
- the string `"*"` for the wildcard;
- an array of `[weak, opaque]` tuples for an entity-tag list.

`weak` is a Boolean. `opaque` is the exact value inside the quotes, without the quotes or `W/` prefix.

The adapter combines folded header fields, parses the HTTP list, removes duplicate tuples, and sorts the remaining tuples. It ignores optional whitespace and input list order.

Tuple order uses ascending ASCII order of the key `0:<opaque>` for a strong tag and `1:<opaque>` for a weak tag. Thus, strong tuples sort before weak tuples.

These syntactic variants produce identical semantic values and request digests. The adapter never digests raw conditional-header bytes.

The value uses only members that the endpoint supports. An absent PATCH property stays absent. An explicit JSON `null` stays `null`.

Path identity is in `normalizedTarget` and is not repeated in this value. Authentication, `Idempotency-Key`, CORS headers, multipart boundaries, and transport header casing are excluded.

The adapter encodes the value with RFC 8785 JSON Canonicalization Scheme. It calculates SHA-256 over the UTF-8 bytes and stores 64 lowercase hexadecimal characters.

Multipart text fields first decode to domain values. A file becomes this semantic value:

```json
{
  "byteLength": 42137,
  "contentType": "application/pdf",
  "sha256": "64-lowercase-hex-characters"
}
```

Part order, boundary text, transfer encoding, temporary path, and client filename do not affect the digest.

### 3.4 Lock, replay, and conflict behavior

The adapter performs these steps in order:

1. Apply route, origin, size, media-type, and structural header checks.
2. Decode the semantic request and resolve the canonical target.
3. Resolve the credential and evaluate the complete 0077.2 `AccessSpec` at the current instant.
4. Apply endpoint concealment before any receipt lookup.
5. Try the transaction-scoped advisory lock for the identity digest.
6. If the lock is held, return 409 `idempotency.in-flight` with `Retry-After: 1`.
7. Read the HTTP receipt while the lock is held.
8. If the receipt digest differs, return 409 `idempotency.digest-conflict`.
9. If a complete receipt matches, return its first response capsule.
10. If no receipt exists, evaluate HTTP preconditions and run the domain command.

Authority always wins over replay. A caller that lost current authority receives the current 401, 403, or concealed 404 response.

A replay never bypasses a revoked session, expired bearer, ended grant, failed requirement, or superseded capability. The adapter does not read response bytes before this decision.

A matching replay ignores the now-stale `If-Match` caused by its own first successful transition. A different `If-Match` changes the digest and returns the digest conflict.

### 3.5 Receipt persistence, privacy, and retention

The implementation adds `native_http_idempotency_receipts`. This table is the HTTP response authority.

| Column            | Contract                                         |
| ----------------- | ------------------------------------------------ |
| `identity_sha256` | Primary key, 64 lowercase hexadecimal characters |
| `request_sha256`  | Canonical semantic request digest                |
| `operation_id`    | Qualified 0077.2 operation ID                    |
| `state`           | `Complete` or `Tombstone`                        |
| `status`          | First HTTP status while `Complete`               |
| `media_type`      | First media type or null                         |
| `body_bytes`      | Exact first body bytes or null                   |
| `headers_json`    | Exact allowlisted response headers or null       |
| `committed_at`    | Database transaction instant                     |
| `full_expires_at` | `committed_at + 24 hours`                        |
| `tombstoned_at`   | Null until redaction                             |

The table does not store the raw key, raw principal identity, raw target, credential, request body, multipart file, cookie, bearer, or capability.

`headers_json` can contain only `content-type`, `etag`, `location`, and `retry-after`. Header names are lowercase. CORS, `Date`, `Server`, `Content-Length`, connection headers, and request-correlation headers are never stored.

After 24 hours, one transaction erases `body_bytes`, `media_type`, `status`, and `headers_json`. It sets `state = Tombstone` and `tombstoned_at`.

A matching tombstone returns 409 `idempotency.response-expired`. A different digest returns `idempotency.digest-conflict`.

A tombstone remains for the lifetime of the corresponding domain command receipt. Current domain receipts are durable, so v0.2 retains the minimal tombstone indefinitely.

This indefinite row contains only the two digests, operation ID, state, and timestamps. A later retention amendment must delete the HTTP and domain receipts together.

### 3.6 Transaction law

An accepted native command uses one PostgreSQL transaction for all applicable rows:

- domain state;
- domain command receipt;
- domain audit;
- zero or more domain outbox requests;
- the complete HTTP idempotency receipt.

The server releases no success response before this transaction commits. A pending outbox request does not change a response to 202.

If a domain currently lacks one required receipt, audit, outbox, or transaction join, its v0.2 migration adds that source. A command with no external effect writes zero outbox rows.

Receipt file bytes can be staged before the transaction. The transaction stores only the staged identity and the outbox request that promotes or deletes it.

A 4xx domain decision after semantic decoding can commit a receipt-only result. A failure that prevents access to the receipt database returns 503 `idempotency.unavailable` and cannot claim replay durability.

## 4. Strong ETags and preconditions

### 4.1 Wire grammar and derivation

Every v0.2 entity tag in this amendment is strong and opaque:

```abnf
Vektor-ETag = DQUOTE "vkr2." 43(base64url-char) DQUOTE
```

A weak tag beginning with `W/` is never emitted. Clients must treat the 43-character token as opaque.

The token is `base64url-no-pad(SHA-256(JCS(source-record)))`. The source record contains only:

- the constant schema version `0.2.0`;
- the representation kind;
- the canonical resource identity;
- the authoritative version scalar or version tuple.

The implementation never hashes mutable response JSON to create an ETag.

### 4.3 Collection validators

A collection source record contains the ordered list of `(resource identity, authoritative revision tuple)` values that can affect its bytes.

Public news also includes the relevant `person_profiles.revision` values for projected author names. A current news item uses `content_articles.current_version_number` and the immutable published version identity.

The open-admission and application-option source records include the applicable admission-period and reference-row revisions. They also include the current half-open time interval between adjacent start or end boundaries.

Crossing an admission boundary therefore changes the validator without a database write. The interval identity is a version source, not response JSON.

### 4.4 Conditional request order

The adapter evaluates conditions only after current credential, authority, scope, requirement, absence, and concealment decisions.

For a request that carries both headers, `If-Match` has precedence over `If-None-Match`.

An existing-resource mutation requires exactly one strong `If-Match` value. A missing value returns 428 `precondition.required`.

A weak tag, wildcard, list, malformed tag, or more than one `If-Match` field returns 400 `precondition.invalid`. A well-formed nonmatching tag returns 412 `precondition.failed`.

A conditional `GET` accepts an `If-None-Match` wildcard or entity-tag list. It uses weak comparison as required by HTTP.

A match returns 304 with no body and no `Content-Type`. The response repeats `ETag`, `Cache-Control`, and `Vary` from the selected 200 response.

If `If-Match` on a read does not strongly match, the response is 412. If it matches, the adapter then evaluates `If-None-Match`.

A concealed credential or authorization failure remains 404. A missing resource remains 404. Neither condition can become 412 or 428.

A valid precondition does not grant authority. An ETag is not a credential, capability, or idempotency key.

## 5. PATCH semantics

JSON PATCH operations accept only `application/merge-patch+json`. Receipt revision accepts only `multipart/form-data`.

A JSON merge-patch body must be an object. An empty object fails with 422 `validation.no-change`.

The adapter reads the current row inside the command transaction. It fills absent fields from that locked row and supplies domain revision values from the matched ETag source.

## 6. Success status, body, and headers

### 6.1 Media types

Every JSON success body uses `application/json`. Every Problem Details body uses `application/problem+json`.

A 204 or 304 response has no body and no `Content-Type`. A multipart request does not make its JSON response multipart.

### 6.2 Read results

Every successful `GET` returns 200 with the schema in 0077.2. These conditional reads can also return 304:

- `organization.listDepartments`;
- `organization.listTeams`;
- `organization.listFieldOfStudies`;
- `admissions.listOpenAdmissionPeriods`;
- `admissions.listApplicationOptions`;
- `admissions.listAdmissionPeriods`;

- `recruitment.readInvitationResponse`;
- `recruitment.readInterviewConduct`;
- `content.readArticle`;
- `content.listNews`;
- `content.readNewsArticle`.

Each listed 200 response emits a strong `ETag`. Other reads return 200 only.

`ReceiptListItem`, `ReceiptApprovalQueueItem`, and `AdmissionPeriodManagementItem` carry item `etag` values. The value validates a later item mutation.

The management collection has its own response `ETag`. This collection tag is not valid as an item `If-Match`.

The first, second, third, fifth, and seventh URIs identify conceptual item resources without adding a new 0077.2 `GET` route. This rule does not authorize a route change.

A 200, 204, 304, 4xx, or 5xx response never includes `Location`, except when a stored first result already contained it.

The API never returns 202 only because an outbox request remains pending.

## 7. RFC 9457 Problem Details

### 7.1 Base schema and namespace

`NativeProblem` is the common public schema:

```ts
type NativeProblem = {
  readonly type: `urn:vektorprogrammet:problem:v0.2:${ProblemCode}`;
  readonly title: string;
  readonly status: number;
  readonly code: ProblemCode;
  readonly detail: string;
  readonly instance?: `urn:uuid:${string}`;
};
```

The frozen type namespace is `urn:vektorprogrammet:problem:v0.2:`. This namespace does not select or authorize a production hostname.

Each `title` and `detail` is a fixed string for its `code`. The `status` equals the HTTP status.

`instance` is an optional request-correlation URN. It never contains the request path, query, person identity, target identity, or credential.

The response never includes a stack, SQL text, internal exception, raw domain message, rejected value, credential, capability, cookie, bearer, email, phone, or file metadata.

### 7.2 Validation extension

Only `validation.failed`, `validation.no-change`, and `validation.field-not-deletable` can add this extension:

```ts
type ValidationProblem = NativeProblem & {
  readonly validation: {
    readonly errors: ReadonlyArray<{
      readonly pointer: string;
      readonly code:
        | "invalid"
        | "missing"
        | "unknown"
        | "duplicate"
        | "out-of-range"
        | "field-not-deletable"
        | "no-change";
      readonly message: string;
    }>;
    readonly truncated: boolean;
  };
};
```

`pointer` is an RFC 6901 pointer into the public semantic request. The array has at most 32 entries and sorts by `pointer`, then `code`.

Each message is a fixed safe message for its code. It does not echo the rejected value.

### 7.4 Challenges, method errors, and retry headers

A cookie-only native endpoint emits this challenge on 401:

```text
WWW-Authenticate: VektorSession realm="native-api"
```

An endpoint that accepts `BetterAuthCookie` and `OAuthUserBearer` emits both `VektorSession` and `Bearer` challenges. An invalid bearer adds `error="invalid_token"` to the Bearer challenge.

An object-capability endpoint applies its 0077.2 concealment. It returns 404 without `WWW-Authenticate` for a missing, malformed, invalid, or unauthorized capability.

A 405 response uses `NativeMethodNotAllowedProblem` with code `method.not-allowed`. It includes `Allow`.

`Allow` lists matrix methods in this order: `GET`, `HEAD`, `POST`, `PATCH`, `DELETE`, `OPTIONS`. It includes `HEAD` when the path has `GET`, and it always includes `OPTIONS`.

The retry headers are exact:

- 409 `idempotency.in-flight` uses `Retry-After: 1`;
- 429 `rate-limit.exceeded` uses a delta between 1 and 3600 seconds from the limiter;
- 503 uses `Retry-After: 5`;
- 500 has no `Retry-After`.

An error response always uses `Cache-Control: no-store`.

## 8. Cache policy

### 8.1 Exact cache classes

The cache policy depends on the route contract, not on ambient credentials.

| Response class                                                            | Exact `Cache-Control`                               |
| ------------------------------------------------------------------------- | --------------------------------------------------- |
| `/api/departments`, `/api/teams`, `/api/field-of-studies` 200 and 304     | `public, max-age=60, s-maxage=300, must-revalidate` |
| `/api/news` and `/api/news/{slug}` 200 and 304                            | `public, max-age=60, s-maxage=300, must-revalidate` |
| `/api/open-admission-periods` and `/api/application-options` 200 and 304  | Dynamic admission policy below                      |
| Any credential-selected read                                              | `private, no-store`                                 |
| `/health`, application confirmation, internal evidence, mutation, and 204 | `no-store`                                          |
| Every 4xx and 5xx response                                                | `no-store`                                          |

The dynamic admission policy is:

```text
ttl = max(0, min(30, floor(seconds until the next relevant startAt or endAt boundary)))
Cache-Control: public, max-age=<ttl>, s-maxage=<ttl>, must-revalidate
```

If no future boundary exists, `ttl` is 30. A boundary at the current instant forces `ttl = 0` and a fresh snapshot.

Anonymous cacheable routes ignore ambient cookie and authorization headers. They never select a private variant and never emit `Set-Cookie`.

No authenticated and anonymous representation shares one route. The separate open-admission and management routes remain mandatory.

### 8.2 Validators and 304

Every cacheable 200 response emits a strong `ETag`. A matching `If-None-Match` returns 304.

The 304 repeats the selected 200 response values for `ETag`, `Cache-Control`, and `Vary`. It has no body, `Content-Type`, or `Location`.

A mutation invalidates the affected projection through its authoritative version source. Cache invalidation is not an outbox-delivery precondition for the transaction.

## 9. Central CORS contract

### 9.1 One configuration authority

The only trusted-origin source is the typed `NativeSessionBoundaryPolicy` decoded from:

- `NATIVE_IDENTITY_DEPLOYMENT`;
- `NATIVE_IDENTITY_TRUSTED_ORIGINS`.

`BETTER_AUTH_URL` and `BETTER_AUTH_TRUSTED_ORIGINS` remain unsupported. A second CORS or trusted-origin source is forbidden.

`NATIVE_IDENTITY_TRUSTED_ORIGINS` is a JSON array of 1 through 16 unique exact origins. An origin has a scheme, host, and optional fixed port.

It has no credentials, path, query, fragment, wildcard, trailing slash, or normalization alias.

The repository-local values are:

| Composition                   | Deployment | Exact value                          |
| ----------------------------- | ---------- | ------------------------------------ |
| Local dashboard               | `local`    | `["http://127.0.0.1:5174"]`          |
| Persistent preview `dev-main` | `preview`  | `["https://vektor.phibkro.org"]`     |
| Pull-request preview `p20`    | `preview`  | `["https://p20.vektor.phibkro.org"]` |

`localhost`, `[::1]`, another port, another `pNNN` host, and `origin-api.vektor.phibkro.org` are not aliases for these values.

Production has no repository-frozen value. Production boot fails until an operator supplies its exact HTTPS origin.

### 9.2 Actual response headers

If `Origin` exactly matches the active list, the response includes:

```text
Access-Control-Allow-Origin: <exact request Origin>
Access-Control-Allow-Credentials: true
Access-Control-Expose-Headers: ETag, Location, Retry-After, WWW-Authenticate
Vary: Origin
```

The adapter emits no wildcard `Access-Control-Allow-Origin`. It never reflects an untrusted origin.

Every native response includes `Vary: Origin`, including a same-origin request without an `Origin` header. Existing `Vary` values are merged without duplicates.

An untrusted credentialed origin fails before credential resolution, receipt lookup, or protected dispatch. It returns 403 `origin.denied`, no CORS allow header, and no mutation.

### 9.3 Preflight

A valid preflight returns 204 with these exact headers:

```text
Access-Control-Allow-Origin: <exact request Origin>
Access-Control-Allow-Credentials: true
Access-Control-Allow-Methods: GET, HEAD, POST, PATCH, DELETE, OPTIONS
Access-Control-Allow-Headers: Authorization, Content-Type, Idempotency-Key, If-Match, If-None-Match, X-Recruitment-Invitation-Capability
Access-Control-Max-Age: 600
Cache-Control: no-store
Vary: Origin, Access-Control-Request-Method, Access-Control-Request-Headers
```

The preflight has no body or `Content-Type`. The origin must be exact.

The requested method must exist for the matched 0077.2 path. Otherwise, the response is 405 with the path-specific `Allow`.

Every requested non-safelisted header must be in the frozen allowlist. Header comparison is ASCII case-insensitive.

An empty header token, duplicate forbidden header, or unsupported requested header returns 400 `header.malformed`. An untrusted origin returns 403 without CORS allow headers.

The same preflight interpreter serves every external native group. The internal API does not enable browser CORS.

## 10. Session and OAuth freeze item

This amendment resolves handoff item 7.6 by adopting 0054.1 and 0082 without creating a second identity contract.

`SessionResponse` exposes only `sessionId`, `personId`, `createdAt`, `updatedAt`, `expiresAt`, `ipAddress`, `userAgent`, and `current`. `SessionListResponse` is an array of that schema.

Session identifiers are opaque and bounded. A response never exposes the session token, cookie, password, credential hash, role cache, grant, or authorization verdict.

The current-session routes accept only `BetterAuthCookie`. Session-list and revocation authority remains owner-only under the exact 0077.2 `AccessSpec`.

The OAuth lifetimes remain:

| Artifact                         |                      Lifetime |
| -------------------------------- | ----------------------------: |
| Authorization code               |                    60 seconds |
| Delegated access token           |                    10 minutes |
| Service access token             |                     5 minutes |
| Refresh token row                | 7 days from issue or rotation |
| Refresh-family inactivity        |                        7 days |
| Refresh-family absolute lifetime |                       30 days |

Refresh tokens rotate on every successful use. `refreshTokenReuseInterval` is zero.

A used refresh token never returns a cached response. Reuse revokes or disables the complete refresh family under the 0082 barrier.

OAuth introspection remains available only at the 0082 provider endpoint and its frozen client authorization boundary. It is not a native operation.

An inactive or unauthorized token introspection returns `200 { \"active\": false }`. Native resource authentication still maps invalid OAuth credentials through 0055.1.

OAuth token, revoke, introspection, authorization, consent, and JWKS responses keep their 0082 protocol semantics. Native Problem Details do not replace OAuth errors.

## 11. Storage and migration cutover

The v0.2 migration contains these explicit source changes:

1. Add `native_http_idempotency_receipts` with the section 3.5 columns and constraints.
2. Add `profile_http_versions(person_id, representation_revision)` and its foreign key to the canonical person.

4. Add nonnegative `revision` to `admission_period_semesters`.
5. Add nonnegative `revision` to `admission_period_fields_of_study`.

The invitation receipt stores its command digest, invitation identity, resulting response revision, and committed instant. It stores no raw capability.

## 12. Deterministic examples

### 12.1 Profile patch and replay

The client first receives:

```http

Cache-Control: private, no-store

```

The client sends:

```http
PATCH /api/profile HTTP/1.1
Content-Type: application/merge-patch+json
Idempotency-Key: MDEyMzQ1Njc4OWFiY2RlZjAxMjM0NTY3ODlhYmNkZWY
If-Match: "vkr2.AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA"

{"phone":"+47 900 00 001"}
```

The adapter keeps all absent profile fields. One transaction updates the contact row, audit, receipts, and applicable outbox rows.

The first result is 200 with the fresh profile and a new ETag. An authorized repeat with identical bytes returns that exact result.

The same key with `{\"phone\":\"+47 900 00 002\"}` returns:

```http
HTTP/1.1 409 Conflict
Content-Type: application/problem+json
Cache-Control: no-store

{"type":"urn:vektorprogrammet:problem:v0.2:idempotency.digest-conflict","title":"Idempotency conflict","status":409,"code":"idempotency.digest-conflict","detail":"This idempotency key identifies a different semantic request."}
```

### 12.3 Receipt multipart canonicalization

These differences do not change the semantic digest:

- a different multipart boundary;
- a different part order;
- a different client filename;
- `amountOre` text that decodes to the same integer.

A different file byte changes its SHA-256 and therefore changes the digest. A missing `file` part on revision means `KeepCurrentFile`.

### 12.4 Concealed invitation

An invalid invitation capability with any `If-Match` returns 404 `resource.not-found`. It has no `WWW-Authenticate` or ETag.

A valid capability and stale ETag returns 412 only after the capability and current requirement pass.

### 12.5 Public conditional read

```http
GET /api/news HTTP/1.1
If-None-Match: "vkr2.BBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB"
Origin: https://vektor.phibkro.org
```

If the tag matches, the response is:

```http
Access-Control-Allow-Credentials: true

```

### 12.6 Trusted preflight

```http
OPTIONS /api/profile HTTP/1.1
Origin: http://127.0.0.1:5174
Access-Control-Request-Method: PATCH
Access-Control-Request-Headers: content-type, idempotency-key, if-match
```

This request receives the exact 204 preflight headers from section 9.3. Replacing the origin with `http://localhost:5174` returns 403.

## 13. Reference tracer journeys

### 13.1 Accepted command, replay, and revoked authority

1. Read a mutable item and record its strong ETag.
2. Send a valid command with a fresh high-entropy key and matching `If-Match`.
3. Observe one domain transition and one committed HTTP receipt.
4. Observe the domain audit and applicable outbox rows in the same transaction.
5. Repeat the request with the same authority, key, ETag, and semantic body.
6. Observe the exact first status, body, media type, `Location`, and ETag.
7. End the grant or revoke the credential.
8. Repeat the request again.
9. Observe the current 401, 403, or concealed 404 and no stored response bytes.

### 13.2 Concurrent duplicate

1. Hold the first transaction after its identity advisory lock.
2. Send the same authorized semantic request concurrently.
3. Observe 409 `idempotency.in-flight` and `Retry-After: 1`.
4. Commit the first transaction.
5. Repeat the request.
6. Observe the exact first result and no second domain transition.

### 13.3 Digest conflict

1. Complete one command.
2. Keep its principal, operation, target, and key.
3. Change one decoded semantic field or file byte.
4. Observe 409 `idempotency.digest-conflict`.
5. Observe no state, audit, outbox, domain-receipt, or HTTP-receipt mutation.

### 13.4 Conditional and concealed read

1. Read a representation and record its ETag.
2. Repeat with matching `If-None-Match` and observe 304.
3. Change the authoritative version source in a supported transaction.
4. Repeat and observe 200 with a different ETag.
5. Remove the caller's authority.
6. Repeat against a concealed endpoint and observe 404, not 304 or 412.

### 13.5 Timed open admission

1. Read open periods before a fixed `startAt` and record the ETag and dynamic TTL.
2. Read at the exact `startAt` instant.
3. Observe changed membership, a changed ETag, and a TTL calculated from the next boundary.
4. Supply a cookie to the anonymous route.
5. Observe the same anonymous bytes and cache policy.

## 14. Falsifiers

The amendment fails if any condition is true:

1. A route, method, operation ID, effect, or `AccessSpec` differs from 0077.2.
2. A `DEP-*` marker reaches code generation or OpenAPI.
3. A public schema contains `commandId` or a replay flag.
4. A public mutation accepts a revision field that belongs in `If-Match`.
5. A mutable item uses a weak ETag, integer ETag, mutable-JSON hash, timestamp alone, or non-authoritative version.
6. A required version source is absent or does not increment with its representation.
7. A concealed denial becomes 401, 403, 304, 412, or 428.
8. A replay reads stored response bytes before current credential and authority evaluation.
9. A matching replay evaluates the stale first `If-Match` before its receipt.
10. A same-key semantic change executes a domain command.
11. An in-flight duplicate waits without bound or returns a status other than the frozen 409.
12. A successful transition commits state without its audit, applicable outbox, domain receipt, and HTTP receipt.
13. An outbox request causes a 202 response.
14. A receipt stores a raw key, credential, capability, principal identity, target, request body, or file.
15. A complete response capsule remains after 24 hours.
16. A tombstone expires while its domain command receipt remains.
17. A PATCH null silently means keep, empty string, or deletion.
18. A multipart boundary, part order, or filename changes the semantic digest.
19. An error uses the v0.1 `{error:{tag}}` envelope.
20. An endpoint exposes an error outside its named problem union.
21. A 500 or 503 exposes an internal exception or rejected value.
22. A 401 lacks the applicable challenge.
23. A 405 lacks the path-specific `Allow`.
24. A 409 in-flight, 429, or 503 lacks its required delta-seconds `Retry-After`.
25. An error or mutation response is cacheable.
26. An authenticated response is stored by a shared cache.
27. An open-admission response remains fresh across a start or end boundary.
28. Anonymous and authenticated admission representations share one route.
29. A credentialed response uses `Access-Control-Allow-Origin: *`.
30. An untrusted origin reaches credential resolution, receipt lookup, or mutation.
31. Localhost, a wildcard, an API-origin host, or an unlisted preview host becomes trusted.
32. A preflight method or header exceeds the frozen list.
33. OAuth protocol errors become native Problem Details.
34. A 201 omits `Location` or changes to 200 on replay.
35. A 204 or 304 includes a body or `Content-Type`.

## 16. Explicit non-goals

This amendment does not implement code, add a route, change an `AccessSpec`, deploy a service, select a production origin, or alter OAuth protocol endpoints.

It does not make outbox delivery synchronous. It does not make a file store part of the PostgreSQL transaction.

It does not define a compatibility route, schema alias, SDK forwarding export, or v0.1 error envelope.
