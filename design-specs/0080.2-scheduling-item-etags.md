# Design spec 0080.2 - scheduling item ETags

## Metadata

| Field | Value |
| --- | --- |
| Stable ID | `0080.2` |
| Status | Frozen before implementation |
| Amends | `design-specs/0080.1-native-http-semantics.md` |
| Dependency | `design-specs/0055.1-principal-credential-access-algebra.md` |
| Scope | `recruitment.readSchedulingBoard` item validators and the scheduling caller contract |

## 1. Amendment authority

This amendment corrects sections 4.2 and 6.2 of design spec 0080.1.

Compatible requirements in design spec 0080.1 remain active. This amendment has authority when a requirement conflicts with this amendment.

## 2. Scheduling item schema

The HTTP response for `recruitment.readSchedulingBoard` uses an HTTP-specific schema. The domain scheduling schema remains independent of HTTP.

Each interview item in the HTTP scheduling board adds this field:

```ts
readonly etag: StrongETag
```

The field contains the strong ETag for that interview. It is not a collection validator.

## 3. Authoritative source

The item ETag uses the exact `RecruitmentInterviewResource` source record from design spec 0080.1. Thus, its derivation uses these values:

1. the schema version `0.2.0`;
2. the representation kind `RecruitmentInterviewResource`;
3. the resource identity `recruitment-interview:${interviewId}`;
4. `recruitment_interviews.revision`;
5. the ordered 0055.1 authority-source tuple for the requesting person.

The authority tuple contains the source references and revisions that determine `canFinalize` and `canCancel`. The item ETag changes when that tuple changes.

The board adapter reads the ordered authority sources for the requesting person once per board request. It does not repeat this read for each interview.

The adapter combines that single authority snapshot with each item identity and interview revision. Each result is the same ETag that the item mutation path calculates.

## 4. Read behavior

`recruitment.readSchedulingBoard` remains a non-conditional read. The response has no collection `ETag` header and does not return 304.

The adapter completes credential and route authorization before it reads ETag sources. A denied or concealed request cannot observe those sources.

Each successful board response contains a valid strong ETag on every interview item. The ETag obeys the wire grammar in design spec 0080.1 section 4.1.

## 5. Mutation handoff

The scheduling caller sends the selected item `etag` unchanged as the `If-Match` header for `recruitment.scheduleInterview`.

The mutation adapter compares that value with the current `RecruitmentInterviewResource` ETag. It preserves the precondition order in design spec 0080.1 section 4.4.

The exact board item ETag succeeds while its source tuple is current. An interview revision change or authority-source revision change makes it stale.

A well-formed stale ETag returns 412 `precondition.failed`. The existing mutation ETag derivation does not change.

## 6. Public schema correction

Design spec 0080.1 section 4.2 includes the following corrected row:

| Representation | Authoritative version source |
| --- | --- |
| `RecruitmentInterviewResource`, each `recruitment.readSchedulingBoard` interview item, `ScheduleInterviewResponse`, `ConductObservation`, finalize responses, and cancel responses | `recruitment_interviews.revision` plus the ordered 0055.1 authority-source revisions that determine `canFinalize` and `canCancel` |

Design spec 0080.1 section 6.2 gains this requirement:

> Each `recruitment.readSchedulingBoard` interview item carries an `etag` value. The value validates a later mutation of that interview.

The list of conditional reads in section 6.2 does not include `recruitment.readSchedulingBoard`.

## 7. Acceptance

The implementation proves these observations:

1. Each scheduling item exposes a valid `StrongETag`.
2. The tag changes when the interview revision changes.
3. The tag changes when a relevant authority-source revision changes.
4. `recruitment.scheduleInterview` accepts the exact tag from the board item.
5. A stale board item tag produces 412 `precondition.failed`.
6. One board request reads the requesting person's ordered authority sources once.
7. Unauthorized requests do not read an interview or its ETag sources.
8. The domain package does not import HTTP schema types.

## 8. Non-goals

This amendment does not add a collection ETag or conditional board behavior. It does not change any interview mutation ETag.

This amendment does not edit a generated release, a generated SDK, or an application caller. Those changes remain dependent on their owning work.

This amendment does not add a route, permission, credential type, or database migration.
