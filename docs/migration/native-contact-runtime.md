# Native contact runtime — spec 0043.1

The command contract is [`SubmitContactMessageEndpoint`](../../packages/http-api/src/contact.ts). Recipient resolution and attempt ordering belong to [`submitContact`](../../packages/domain/src/contact/service.ts); quota admission is an atomic PostgreSQL upsert in [`ContactQuotaLive`](../../packages/domain/src/contact/postgres.ts). The first admitted attempt starts an hour; further attempts do not extend it. Five decoded attempts are allowed. Expired metadata is pruned on contact attempts; if traffic stops, expired records remain until the next attempt. No message body is persisted.

```text
Visitor → controlled ingress (socket/edge IP, strips incoming contact forwarding headers)
  → Worker (authenticates ingress token, creates typed request context)
    → SDK (exact backend origin, rejects redirects, separate backend token)
      → native command (credential → schema → committed quota → Organization recipient → delivery ACK)
```

This topology requires **two distinct server-only credentials** of at least 32 characters. The Worker receives `CONTACT_INGRESS_TOKEN`, `CONTACT_BACKEND_TOKEN`, and exact-origin `API_URL` bindings. The controlled ingress sets `x-vektor-contact-ingress` and `x-vektor-contact-ip` from its runtime address, overriding visitor input. Unsupported/direct uncredentialed submissions fail closed. A credential grants the forwarding authority of its hop, so deployment must keep it out of browsers and untrusted ingress processes. Cloudflare header names alone confer no trust.

The backend receives `CONTACT_BACKEND_TOKEN`, `CONTACT_SENDER`, `CONTACT_DELIVERY_URL`, `CONTACT_DELIVERY_TOKEN` and explicit `CONTACT_DELIVERY_TIMEOUT_MS` (1–30000). Missing or invalid configuration disables the command. Delivery is one acknowledged JSON POST using the [existing application HTTP transport](../../apps/backend/src/delivery/http.ts), now shared by both callers. The envelope contains `from`, organization-derived `to`, visitor `replyTo`, `[Kontaktskjema] `-prefixed `subject`, and `text` formatted as the legacy `Navn`/`E-post` header followed by the message; the transport uses its own bearer credential. No automatic retry or exactly-once claim exists. HTTP201 means transport acceptance, not inbox delivery; an ambiguous timeout may have delivered, and a later visitor retry can duplicate it. Invalid recipient and transport failures do not refund quota. A429 response conservatively asks the caller to wait one hour.

Before a local run, build the SDK and homepage from a clean committed tree. Then run `bun run --cwd apps/homepage e2e:contact:native`. The [runner](../../apps/homepage/e2e/run-native-contact.mjs) owns temporary PostgreSQL, synthetic organization fixtures, ephemeral hop/delivery credentials, the actual built Worker in Miniflare, a socket-derived Node ingress and a loopback receiver. It requires installed PostgreSQL tools and Chromium (`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` can override the workstation path). It never calls an external mail provider. It writes evidence under a new `/tmp/vektor-contact-0043-*` directory and stops owned processes and removes the disposable database. The evidence lists its exact source revision and gates; a failure is never a successful skipped run.

Source reuse: the SDK derives operations from `ExternalNativeApi`; use HTTP/docs generators after contract edits. The parser is the existing MIT-licensed `ip-address@10.7.0`, made an explicit domain dependency, including IPv4-mapped IPv6 normalization. JSON decoding reuses the backend duplicate-member parser with a streaming byte limit. The runtime follows the existing PostgreSQL real-journey runner pattern and the installed Cloudflare runtime. References: [PostgreSQL INSERT](https://www.postgresql.org/docs/current/sql-insert.html), [React Router createContext](https://reactrouter.com/api/utils/createContext), [Workers best practices](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/).

The existing live preview503 has been separately diagnosed by the coordinating lead as duplicate active department slugs. This implementation preserves the specified503 response, and the runner introduces the same collision in isolated fixtures. A successful seeded run does not repair or verify live preview data. Production ingress/provisioning, deployment, reCAPTCHA parity and default-department geolocation remain outside this contract.
