# Synthetic receipt import rehearsal (0095)

Run `bun run --cwd packages/database rehearsal:receipt-import` from a clean committed checkout with installed workspace dependencies and local `initdb`, `postgres`, `pg_dump`, `pg_restore` and Bun. The command allocates private loopback ports and disposable PostgreSQL; it accepts no external database or source-data argument. No provider configuration may be inherited. Evidence is retained under `/tmp/vektor-receipt-0095-*` only after owned process cleanup succeeds.

The immutable synthetic manifest binds each row digest to explicit User/Person and Department mappings and bounded source files. The adapter uses the existing Receipt transformer and transactional ledger. The existing private store stages and promotes actual bytes; facts/ledger then commit atomically in PostgreSQL. Files and SQL are not a distributed transaction. A failed ledger write leaves no visible receipt; retry uses deterministic file identity. Rejected staging objects are removed only when no committed receipt references them.

Fresh reconciliation compares the locked persisted receipt against its source fact, then checks its native owner projection and authenticated private-byte download. The ledger records the last observation as Reconciled or Pending; every new observation checks again, including after tampering. A prior marker never skips IO. Imports issue no user-command outbox effects; the real outbox interpreter is exercised with a rejecting auxiliary service and an outside-transaction attempt counter.

The new owner-only `GET /api/receipts/:receiptId/file` resolves credentials and owner evidence in one read snapshot before storage IO. Verified bounded bytes return as a binary attachment with private no-store and nosniff headers; foreign/missing owners are concealed and mismatched/missing bytes fail unavailable. No approver download/UI capability is added.

The rehearsal separately seeds a pre-existing native receipt/private file and disposable verified auth accounts, then backs up the owned DB and file inventory before the import window. It restores into a second owned database and file destination and compares facts, original bytes and fixture credentials. This is local restore evidence, not a production rollback or password-migration mechanism. Receipt notification delivery remains the existing recording default at the backend composition root; no provider is wired here.
