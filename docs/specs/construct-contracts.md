# Construct contracts

Status: frozen for implementation on 2026-09-26 (operator request). Remove this specification when the checks below run in hooks and CI and the effect-house overlay and `AGENTS.md` describe the new pages.

## Problem

`docs/constructs.md` loads 117 KB into a reader's context, and 88 KB of it are consumer links. A reader who wants to know what a construct does gets a one-line summary and a list of importers. The contract is missing: what it takes, what it returns, how it fails, what it needs, and what it changes. Because the page lists importers, every import change rewrites it (45 commits in three days), which causes rebase conflicts between unrelated branches.

## Goal

Reading about constructs discloses in three steps, each loaded only when needed:

1. **Index** (`docs/constructs.md`): each category and each construct as one line, with a link to its contract. It does not change when imports change.
2. **Contract** (`docs/constructs/<category>.md`): for each construct, how it works, its inputs, its output, its errors, its requirements, its side effects, how to use it, and how not to use it.
3. **References**, on explicit request only: `just constructs consumers <name>` prints the modules that import a construct. No page lists them.

## Contract content and its sources

Each fact has one source. Facts the types already state are generated from them; the prose covers only what the types cannot say.

| Section | Source |
| --- | --- |
| Summary | first JSDoc sentence (as today) |
| Signature, inputs, output | the declaration's parameter and return type annotations, as written. A construct declares both explicitly; a missing annotation is a finding. |
| Errors and requirements | the `E` and `R` of a returned `Effect<A, E, R>`, or the failure side of a returned `Result`/`Option`, split out of the annotation. `never` renders as "none". |
| How it works | `@remarks` |
| Side effects | `@sideEffects`: writes, locks, I/O, time, randomness, or `none` |
| Use | `@example`: one call as a consumer writes it |
| Avoid | `@avoid`: the misuse the construct exists to prevent, and what to do instead |
| Source | a link to the declaration line |

A tagged construct without each required tag is a finding, so the contract cannot silently go missing.

## Rules

- The index and contract pages are generated by `just constructs write` and checked by `just constructs`, as the page is today. They are not edited by hand.
- The pages depend only on the tagged declarations and their JSDoc, never on the import graph.
- `just constructs consumers <name>` reads the import graph when called. With no name it lists each construct with its consumer count.
- The rule "tag a construct only when at least two call sites share its logic" becomes a check: a construct with fewer than two consumers outside its own module and tests is a finding. Measure the count first. Fix each such site by removing the tag or by moving real reuse onto the construct.
- The effect-house overlay, the construct section of `AGENTS.md`, and `tools/conventions/AGENTS.md` describe the three steps.

## Done when

1. `docs/constructs.md` is at most 20 KB, lists every construct in one line each, and contains no consumer path.
2. Every construct has a contract section with every row of the table above. Removing a required tag from one construct makes `just constructs` exit 1 (negative control), and so does removing a return type annotation.
3. Adding an import of a construct to a new module leaves every generated page byte-identical (test).
4. `just constructs consumers <name>` prints the same importers the old page listed for three sample constructs.
5. The consumer-count finding is on, with no findings on main.
6. `just check` and the hosted Checks workflow pass.
